# Local Arcade

## 프로젝트 명

**Local Arcade — LAN 기반 실시간 멀티플레이 게임 플랫폼**

## 개발환경

- OS: Windows
- Frontend: React 18.3, TypeScript 5.7, Vite 6, HTML5, CSS3, Fetch API
- Backend: Java 21, Spring Boot 3.4, Spring Web MVC, Spring Data JPA, Spring Validation, REST API
- Database / ORM: MySQL 8, JPA / Hibernate
- AI: OpenAI Responses API, Structured Outputs(JSON Schema), LLM Wiki(Markdown)
- Security / Protocol: HTTP, REST, Bearer 세션 토큰, 관리자 코드 인증, LAN TCP/IP
- Infra / Runtime: 동일 LAN 네트워크, Embedded Tomcat, Vite Proxy
- Build / Package: Maven Wrapper, npm
- Output: 멀티플레이 웹 게임, LLM 학습 퀴즈, 관리자 대시보드
- Tool: Visual Studio Code, IntelliJ IDEA
- 형상관리: Git / GitHub

## 사용언어

- TypeScript
- Java
- HTML5 / CSS3
- SQL

## 프로젝트 소개

Local Arcade는 최대 6명이 참여 코드로 접속해 야추, 레이싱, 채팅, LLM 위키 퀴즈를 함께 즐기는 LAN 기반 멀티플레이 웹 플랫폼입니다.  
서버 중심의 게임 상태·크레딧 관리와 캐릭터 이동 및 애니메이션을 구현해 안정적인 멀티플레이 경험을 제공합니다.

### 주요 기능

#### 야추

2명 이상이 참가 점수를 걸고 즐기는 턴제 주사위 게임입니다. 한 턴에 최대 세 번 주사위를 굴리고 원하는 주사위를 고정한 뒤, 12개 점수 항목 중 하나를 선택합니다. 서버가 주사위 결과와 점수표를 검증하여 화면 조작을 방지하고, 모든 라운드 종료 후 합계·상단 보너스·공동 우승을 계산해 크레딧을 자동 분배합니다. 준비 상태, 턴 전환, 재경기, 기권과 환불까지 실제 멀티플레이 흐름을 구현했습니다.

#### 달팽이 레이싱

플레이어가 다섯 달팽이 중 하나를 선택해 크레딧을 걸고 함께 결과를 확인하는 멀티플레이 게임입니다. 서버에서 순위를 무작위로 결정하고 모든 참가자에게 같은 경기 결과를 전달하며, 프론트엔드는 카운트다운·주행 애니메이션·시상대 연출로 결과를 시각화합니다. 게임 결과를 서버의 고유 경기 ID로 구분하여 중복 애니메이션과 상태 불일치를 줄였습니다.

#### LLM 위키 퀴즈

직접 정리한 개발 학습 위키를 기반으로 LLM이 객관식 문제를 생성하는 학습형 콘텐츠입니다. 단순 생성에 그치지 않고 위키 원문 발췌만을 근거로 사용하도록 제한했으며, JSON Schema 기반 Structured Outputs로 문제·선택지·정답·해설·출처 형식을 일관되게 유지했습니다. 최근 20개 문제 이력을 비교해 중복 출제를 줄이고, 생성 결과의 출처와 정답 범위를 서버에서 다시 검증합니다. 생성 기능을 끈 경우에는 DB에 저장된 검증 문제를 재사용하여 API 비용과 서비스 연속성을 함께 고려했습니다.

#### 캐릭터 이동 및 애니메이션

방향키 이동, Shift 달리기, 점프와 발판 착지를 지원하는 2D 캐릭터 조작 데모입니다. `requestAnimationFrame`과 프레임 간 시간 차이를 이용해 기기 성능과 관계없이 일정한 이동 속도를 유지하고, 중력·수직 속도·바닥 및 발판 충돌을 계산했습니다. 입력과 현재 상태에 따라 idle, walk, run, jump 애니메이션을 자연스럽게 전환하며 캐릭터 방향도 실시간으로 반영합니다.

#### 실시간 채팅

게임을 플레이하면서 모든 접속자가 대화할 수 있는 공용 채팅을 구현했습니다. 메시지 길이와 공백 입력을 서버에서 검증하고, 순번·닉네임·전송 시각을 포함한 최근 80개의 메시지를 관리합니다. 클라이언트는 주기적으로 서버 상태를 동기화하고 새 메시지가 도착하면 채팅 영역을 자동으로 스크롤합니다.

#### 크레딧 및 운영 관리

모든 게임의 참가비·보상·퀴즈 정답 보상을 하나의 크레딧으로 통합했습니다. 크레딧 증감과 게임 결과 처리는 서버 트랜잭션 안에서 수행해 데이터 일관성을 확보했으며, 랭킹 화면에서 실시간 순위를 확인할 수 있습니다. 별도의 관리자 페이지에서는 관리자 코드 인증 후 접속자 조회, 크레딧 지급·차감, 사용자 퇴장, LLM 신규 문제 생성 활성화 여부를 관리할 수 있습니다. 크레딧은 결제·충전·출금·환전이 불가능한 게임 점수입니다.

## 역할

**개인 프로젝트 / 기여도 100%**

- React와 TypeScript를 활용한 게임 UI, 반응형 화면 및 애니메이션 구현
- Spring Boot REST API와 JPA 기반 플레이어·게임·크레딧 데이터 처리
- 야추 점수 계산, 레이싱 결과, 턴과 참가 상태 등 멀티플레이 게임 규칙 설계
- 참여 코드 및 토큰 기반 세션, 비활성 사용자 정리, 관리자 기능 구현
- OpenAI Responses API와 로컬 위키를 연동한 퀴즈 생성·검증·저장 구조 설계
- 프론트엔드 폴링과 서버 명령 큐를 통한 다중 사용자 상태 동기화

## 프로젝트 후기

이번 프로젝트를 통해 게임 화면을 만드는 것보다 여러 사용자가 공유하는 상태를 정확하게 관리하는 일이 더 중요하다는 점을 배웠습니다. 특히 야추의 턴과 점수표, 레이싱의 단일 경기 결과, 크레딧 정산처럼 동시에 요청이 들어올 수 있는 기능은 서버를 최종 판단 주체로 두고 검증해야 안정적으로 동작했습니다.

LLM 퀴즈를 구현하면서는 생성형 AI의 응답을 그대로 사용하는 대신, 근거 문서 제한·구조화된 출력·서버 검증·중복 방지·저장 문제 대체 흐름을 함께 설계해야 실제 서비스 기능으로 활용할 수 있다는 점을 경험했습니다. 또한 캐릭터 조작과 게임 애니메이션을 구현하며 상태 관리, 시간 기반 움직임, 사용자 입력과 시각적 피드백을 자연스럽게 연결하는 방법을 익혔습니다.

### 로컬 실행

MySQL 8 이상을 실행한 뒤 백엔드와 프론트엔드를 각각 시작합니다. 기본 API 포트는 `8081`, 게임 화면은 `5173`입니다.

```powershell
cd backend
.\mvnw.cmd spring-boot:run
```

```powershell
cd frontend
npm.cmd install
npm.cmd run dev
```

서버 콘솔에 표시된 6자리 참여 코드를 입력해 접속합니다. 같은 네트워크의 다른 기기에서는 `http://실행PC의-IP:5173`으로 접속할 수 있습니다.

### 최대 6명 동시 요청 테스트

백엔드를 실행한 뒤 콘솔에 표시된 참여 코드를 전달하면 다음 항목을 자동 검증합니다.

- 테스트 사용자 6명 동시 입장
- 6명 야추 참가 요청 동시 실행 및 크레딧 1회 차감 확인
- 동일 사용자의 중복 참가 요청 5건 거절 확인
- 6명 × 2개 상태 API 반복 조회와 응답 시간 측정
- Markdown 결과 보고서 자동 저장

```powershell
python scripts\local_arcade_concurrency_test.py --join-code 123456
```

결과 보고서는 기본적으로 `reports` 폴더에 생성됩니다. 이 테스트는 동일 LAN 최대 6명이라는 프로젝트 요구사항에 맞춘 기능·동시성 검증이며 대규모 부하 테스트가 아닙니다.
